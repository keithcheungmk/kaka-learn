# 檢查 Agent 規則（kaka-learn）

用途：merge 前由「檢查 agent」用**中文、人話**睇一次；實作 agent 負責處理所有問題，處理完先可以 merge。

**產品擁有人唔使親自檢查。** 唔好問「睇吓得唔得／請你檢查／要唔要 deploy」。檢查通過就直接 merge／部署。

---

## 角色分工

- **實作 agent**：寫功能、修 bug、commit、等檢查。
- **檢查 agent**：唔寫功能；只讀 diff 同預覽，出**檢查報告**。
- **結論只有兩種**：
  - `可以 merge`（冇 blocker）
  - `有問題`（列出點解；實作 agent 要修到好為止）

---

## 檢查清單（逐條過）

### A. 冇破壞現有嘢（最重要）

- 主頁三個入口都**開到**：認字、字母隊、小鹿數理探險（先揀小朋友 Profile）。
- 改數理唔可以令認字／字母隊白屏、冇反應或入唔到。
- 兩個 Profile 要分倉；換人之後幣／進度唔好互串。

### B. 畫面完成度（唔係半成品）

- 目標頁面要**見到內容**，唔係空白、唔係「即將開放」除非原本設計係咁。
- 所有文字要**完整顯示**（唔好被切、被遮）。
- 圖片／icon 要**真係載入到**（冇破圖、冇 404）。
- 按鈕要**撳得郁**（唔會重疊到撳唔中）。

### C. 視覺／UI 問題（你哋最常見；要逐項睇）

1. **對比度**
   - 深底上嘅字要夠光；淺底上嘅字要夠深。
   - 重要提示（答啱／答錯）唔可以淡到睇唔到。

2. **遮擋／重疊**
   - 文字唔好俾圖、針、邊框遮到睇唔清。
   - 卡片／按鈕唔好互相疊住。

3. **間距**
   - 按鈕同內容之間要有位，唔好貼死邊。
   - 長內容要可以**滾動**或**包住**，唔好爆出版面。

4. **字體大小**
   - 幼齡要夠大；重要數字／字詞唔好細到難讀。
   - 標題同內容層次要清楚。

5. **一致性**
   - 同一類畫面（先學／去玩玩／答題）風格要一致。
   - 顏色唔好突然多咗好亂嘅色相（跟返該頁主題）。

6. **圖示／圖片**
   - 要用得啱主題（例如鐘就係鐘，唔好變咗第二樣嘢）。
   - 第三方圖要有 **credits** 同授權說明。

7. **動畫**
   - 唔好閃到眼痛；過場要短、有意義。
   - 答錯唔好用刺眼紅色／嚇親人嘅效果。

8. **版心**
   - 主要內容要大致置中／對齊，唔好歪去一邊。

### D. 適合約 4 歲

- 答錯文案要**溫柔**（「再試吓」），**唔好**「錯咗／好蠢」。
- 唔好突然加**計時壓力**、排名、羞辱。
- 操作流程要**簡單**：一頁唔好塞太多任務。
- **砌一砌**淡色格顯示目標漢字係**刻意支架**（配對／重複活動學習），**唔好**當洩題叫人刪走。
- 學習頁「去玩玩」常駐（唔使揭完先出）；睇完最後一張之後改「學完喇・去玩玩」並加強。誤撳「再睇一次」唔好隱藏。
- 遊戲畫面**唔使捲**：字池、目標格、圖要一屏見晒（`smoke-shots.py` 會自動驗）。
- 遊戲畫面：今輪進度條（8 或 10 格），答啱**有粒星由圖卡飛去條 bar**，落地先亮，後面有硬幣同「仲差 N 題」。
- 主頁／揀主題／學習頁：今日三個幣位（聽／配／砌），賺咗嘅亮金。
- 完成一輪要真係派幣；同一種玩法一日第二次完成唔會再派（會講「試下第二個玩法」）。
- **每個插圖都要睇得清楚**：OpenMoji 黑線條圖一定要坐喺淺色圓碟上（冇圓碟＝一堆字睇落好似冇圖）。
- 聲音要係女聲（自動揀粵語女聲）。
- 畫面**唔需要放大縮細**；iPad 螢幕兩指同妙控鍵盤觸控板 pinch 都唔好放大成個 app。
- 揀玩法頁三張圖卡要睇得出聽一聽、配一配、砌一砌；標題統一叫「配一配」；文字唔好被切。
- 認字玩法一輪：聽／配 **8 個 unique 字**（主題少過 8 就全清）；砌一砌 **10 個**（主題少過 10 就全清）。答錯唔清零、唔計入進度。

### E. 數理模組專用規則

- **故障隔離**：`math-app.js` 壞咗，認字／字母隊要照開到。
- **儲存**：數理用 `kaka-math-v1`；唔好寫亂認字嘅 `kaka-learn-v1`。
- **星球旅程**：點亮／飛去下一粒要同而家設計一致（唔硬鎖）。
- **星星**：數理星星上限同邏輯唔好偷偷改咗。

### F. 技術底線

> **先跑機器檢查**：`python3 scripts/check-invariants.py`。
> Exit 0 先好人手睇下面；exit 1 = 自動「有問題」，實作 agent 要修到綠先再檢查。
> 佢已經自動覆蓋：JS syntax、24 個核心動物字、鹿類規則、`.build-ghost`、完成一輪派幣、
> Profile 分倉、鎖放大、三個入口、storage 鍵分家、數理故障隔離、asset 404、圖片大細、外部依賴。
> 跟住跑 `python3 scripts/smoke-shots.py --no-shots`（要 `python3 -m http.server 5173` 開住）：
> **預設家庭裝置**——iPad Pro 11 直／橫 + iPhone 16 Pro Max 直（共 3 個 viewport）× 全程畫面，
> 檢查**溢出、元素重疊、內容被剪走**、白屏、404、console error。舊全尺寸用 `--all`。
> **iPad 遊戲畫面要捲 = blocker**（KAKA 拖字會捲親）；只有揀主題／揀書准捲。
> **手機**准捲，但**唔可以重疊、唔可以剪走內容**。
> 檢查 agent 主力睇機器睇唔到嘅嘢：**視覺、幼齡適切度、玩法邏輯**（就住最多 2 張截圖睇）。
> **唔好**再開 computerUse 重跑 smoke／行完整認字——燒 token、拖時間。

- JS 要**語法正確**（新／改嘅檔要 parse 到）。
- 新檔案／圖／樣式要**真係喺 PR 入面**（唔好淨係本機有）。
- 唔好引入唔必要嘅外部依賴（保持純靜態、無 build）。

## 報告格式（檢查 agent 要跟）

```text
結論：可以 merge / 有問題

改咗咩：
- …（一句）

影響：
- 認字：有/冇
- 字母隊：有/冇
- 數理：有/冇

檢查重點：
- 視覺：OK / 問題（邊頁、咩位）
- 幼齡：OK / 問題
- 技術：OK / 問題

要修：
- （有問題先寫；冇就寫「無」）
```

- **例外先准短 computerUse**（仍然唔好拍長片）：改 CSS 動畫／飛星／過場；或者 smoke 綠但懷疑互動壞（撳掣無反應）
- Keith 冇明確要求就**唔好**為檢查再開第二個 subagent

| 步驟 | 做咩 | 時間上限 |
|------|------|----------|
| 0 | 睇 CI／`qa-report.py`；exit ≠0 → 「有問題」 | 2 min |
| 1 | `git diff --stat`；**只 review 改動模組** | 1 min |

| 3 | 報告「視覺／幼齡」各 ≤2 行 → 結論 | 1 min |

### Diff 範圍（唔使全 app E2E）

- 只改 `words.js` → 驗受影響主題學習／玩法一屏
- 只改 `index.html` 主頁 → 驗主頁 + 四入口可開
- 只改 `star-fx.js` / ranger 圖 → 驗一個玩法屏 + 飛星（截圖／短片擇一）
- 只改 `math-*` → 驗數理 + 認字／字母隊仍可進入

### Token／時間節省（硬性）

- **唔再**自己重跑 `check-invariants.py`／`smoke-shots.py`（CI 已跑；實作 agent 本地跑過就夠）
- **唔用** browser agent 行完整認字／字母隊／數理流程
- **唔錄** demo 片，除非動畫例外
- **唔 fork** 額外檢查 subagent「再驗一次」
- 報告總長 **≤12 行**
- 目標：檢查 agent 牆鐘 **≤5 分鐘**（以前 ≤10）

## 實作 agent 要點做

0. `python3 scripts/check-invariants.py` 跑到綠
1. push branch（CI 會再跑一次）
2. 跑 `python3 scripts/qa-report.py`，將輸出貼俾檢查 agent（唔好叫產品擁有人檢查）
3. **所有「有問題」都要處理**（修／再推／再檢查）
4. 檢查 agent 講「可以 merge」→ **即刻 merge 入 `main`**（GitHub Pages 會自動部署；唔使再問要唔要上線）
5. merge 後只通知產品擁有人：做咗咩、live 網址、上線未

### 硬性：唔好問用戶檢查

- **禁止**：「請你睇吓」「確認下得唔得先部署」「要我 merge 嗎？」
- **應該**：檢查 agent 通過 → merge → 話你知已經上線（或部署緊）
- 只有檢查 agent **未跑**或結論 **有問題** 先停；唔好停低等用戶 QA
