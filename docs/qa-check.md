# 檢查 Agent 規則（kaka-learn）

用途：merge 前由「檢查 agent」用**中文、人話**睇一次；實作 agent 負責處理所有問題，處理完先可以 merge。

**產品擁有人唔使親自檢查。** 唔好問「睇吓得唔得／請你檢查／要唔要 deploy」。檢查通過就直接 merge／部署。

---

## 角色分工

- **實作 agent**：寫功能、修 bug、commit、等檢查。
- **檢查 agent**：唔寫功能；只讀 diff 同預覽，出**檢查報告**。
- **結論只有兩種**：
  - `可以 merge`（冇 blocker）
  - `有問題`（列出點解；實作 agent 要修到好為止）

---

## 檢查清單（逐條過）

### A. 冇破壞現有嘢（最重要）

- 主頁三個入口都**開到**：認字、字母隊、小鹿數理探險。
- 改數理唔可以令認字／字母隊白屏、冇反應或入唔到。
- 家長區／PIN 流程唔可以被改壞。

### B. 畫面完成度（唔係半成品）

- 目標頁面要**見到內容**，唔係空白、唔係「即將開放」除非原本設計係咁。
- 所有文字要**完整顯示**（唔好被切、被遮）。
- 圖片／icon 要**真係載入到**（冇破圖、冇 404）。
- 按鈕要**撳得郁**（唔會重疊到撳唔中）。

### C. 視覺／UI 問題（你哋最常見；要逐項睇）

1. **對比度**
   - 深底上嘅字要夠光；淺底上嘅字要夠深。
   - 重要提示（答啱／答錯）唔可以淡到睇唔到。

2. **遮擋／重疊**
   - 文字唔好俾圖、針、邊框遮到睇唔清。
   - 卡片／按鈕唔好互相疊住。

3. **間距**
   - 按鈕同內容之間要有位，唔好貼死邊。
   - 長內容要可以**滾動**或**包住**，唔好爆出版面。

4. **字體大小**
   - 幼齡要夠大；重要數字／字詞唔好細到難讀。
   - 標題同內容層次要清楚。

5. **一致性**
   - 同一類畫面（先學／去玩玩／答題）風格要一致。
   - 顏色唔好突然多咗好亂嘅色相（跟返該頁主題）。

6. **圖示／圖片**
   - 要用得啱主題（例如鐘就係鐘，唔好變咗第二樣嘢）。
   - 第三方圖要有 **credits** 同授權說明。

7. **動畫**
   - 唔好閃到眼痛；過場要短、有意義。
   - 答錯唔好用刺眼紅色／嚇親人嘅效果。

8. **版心**
   - 主要內容要大致置中／對齊，唔好歪去一邊。

### D. 適合約 4 歲

- 答錯文案要**溫柔**（「再試吓」），**唔好**「錯咗／好蠢」。
- 唔好突然加**計時壓力**、排名、羞辱。
- 操作流程要**簡單**：一頁唔好塞太多任務。
- **砌一砌**淡色格顯示目標漢字係**刻意支架**（配對／重複活動學習），**唔好**當洩題叫人刪走。
- 學習頁睇完最後一張之後，「學完喇・去玩玩」要一直留底；誤撳「再睇一次」唔好隱藏。
- 遊戲畫面**唔使捲**：字池、目標格、圖要一屏見晒（`smoke-shots.py` 會自動驗）。
- 星星條要見到：十格，答啱亮一粒，後面有硬幣同「仲差 N 粒」。
- **每個插圖都要睇得清楚**：OpenMoji 黑線條圖一定要坐喺淺色圓碟上（冇圓碟＝一堆字睇落好似冇圖）。
- 聲音要係女聲；家長區可以揀聲同試聽。
- 畫面**唔需要放大縮細**；iPad 螢幕兩指同妙控鍵盤觸控板 pinch 都唔好放大成個 app。
- 揀玩法頁三張圖卡要睇得出聽、睇圖揀字、用手砌；文字唔好被切。
- 認字玩法一輪：聽／配 **8 個 unique 字**（主題少過 8 就全清）；砌一砌 **10 個**（主題少過 10 就全清）。答錯唔清零、唔計入進度。

### E. 數理模組專用規則

- **故障隔離**：`math-app.js` 壞咗，認字／字母隊要照開到。
- **儲存**：數理用 `kaka-math-v1`；唔好寫亂認字嘅 `kaka-learn-v1`。
- **星球旅程**：點亮／飛去下一粒要同而家設計一致（唔硬鎖）。
- **星星**：數理星星上限同邏輯唔好偷偷改咗。

### F. 技術底線

> **先跑機器檢查**：`python3 scripts/check-invariants.py`。
> Exit 0 先好人手睇下面；exit 1 = 自動「有問題」，實作 agent 要修到綠先再檢查。
> 佢已經自動覆蓋：JS syntax、24 個核心動物字、鹿類規則、`.build-ghost`、每日 10 星上限、
> PIN 預設、鎖放大、三個入口、storage 鍵分家、數理故障隔離、asset 404、圖片大細、外部依賴。
> 跟住跑 `python3 scripts/smoke-shots.py`（要 `python3 -m http.server 5173` 開住）：
> 5 種 iPad 尺寸 × 9 個畫面，檢查**溢出（要唔要捲）**、白屏、404、console error，並影低截圖落 `.smoke/`。
> **遊戲畫面要捲 = blocker**（KAKA 拖字會捲親）；只有揀主題／揀書准捲。
> 檢查 agent 主力睇機器睇唔到嘅嘢：**視覺、幼齡適切度、玩法邏輯**（就住啲截圖睇）。

- JS 要**語法正確**（新／改嘅檔要 parse 到）。
- 新檔案／圖／樣式要**真係喺 PR 入面**（唔好淨係本機有）。
- 唔好引入唔必要嘅外部依賴（保持純靜態、無 build）。

## 報告格式（檢查 agent 要跟）

```text
結論：可以 merge / 有問題

改咗咩：
- …（一句）

影響：
- 認字：有/冇
- 字母隊：有/冇
- 數理：有/冇

檢查重點：
- 視覺：OK / 問題（邊頁、咩位）
- 幼齡：OK / 問題
- 技術：OK / 問題

要修：
- （有問題先寫；冇就寫「無」）
```

---

## 實作 agent 要點做

0. `python3 scripts/check-invariants.py` 跑到綠
1. push branch（CI 會再跑一次）
2. **自己叫檢查 agent 出報告**（唔好叫產品擁有人檢查）
3. **所有「有問題」都要處理**（修／再推／再檢查）
4. 檢查 agent 講「可以 merge」→ **即刻 merge 入 `main`**（GitHub Pages 會自動部署；唔使再問要唔要上線）
5. merge 後只通知產品擁有人：做咗咩、live 網址、上線未

### 硬性：唔好問用戶檢查

- **禁止**：「請你睇吓」「確認下得唔得先部署」「要我 merge 嗎？」
- **應該**：檢查 agent 通過 → merge → 話你知已經上線（或部署緊）
- 只有檢查 agent **未跑**或結論 **有問題** 先停；唔好停低等用戶 QA
