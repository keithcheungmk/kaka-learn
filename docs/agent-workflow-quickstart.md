# Agent 工作流程速覽

給所有模型使用。這是導航，不是規則或現況的另一份來源；完整規則見 `AGENTS.md`，協作及未核實工作見 `docs/handover.md`。用戶本次指示及較新、明確的項目決定優先於舊記錄。不要把舊記錄當成目前已完成或已上線。

## 開工

1. 說清楚目標、範圍及完成條件。大型功能或產品方向先提方案及 demo，按用戶既有指示處理。
2. 讀 `AGENTS.md` 和 `docs/handover.md`。核對認領、高危共享檔、相關近期記錄及原始需求；不確定狀態時查 Git、PR 或實際產物。
3. 修改前 fetch 主線，核對工作樹、最新主線及部署。若舊 checkout 有其他未提交工作，從最新主線開獨立工作目錄，保留原有工作。不可用舊檔覆蓋新版本。
4. Chief 指派既有專科 Lead，一項任務一位主責；共享檔先認領。Lead 不可自行新增下屬或開 cloud agent。

## 按任務讀資料

| 任務 | 負責／先讀 | 額外檢查 |
|---|---|---|
| 中文、紅／橙輯、PTH | Chinese Lead；`docs/word-card-ocr.md` 或相關中文規格 | 逐字核對原始資料；字卡用 `scripts/apply-book-cards.py` 先 dry-run。PTH 媒體與詞音規則見 `AGENTS.md`。 |
| 英文、Carter、Phonics | English Lead；相關內容與錄音資料 | 保留頁碼與音檔來源。播放自動測試不等於人耳聽審。 |
| 數學 | Math Lead；`docs/math-brief.md` | 核對題目、答案、自然粵語與獨立進度。 |
| 共用入口、Profile、CI 或部署 | Chief 指派一位 Lead；`docs/qa-check.md` | 先核對共享檔認領、相關使用流程和發布權限。 |
| 素材 | 相應 Lead；`AGENTS.md` Source Materials | 原件留在 `source-materials/`，只產生有來源記錄的必要衍生品；發布前檢查私隱。 |

## 檢查與交付

1. 按實際 diff 確定受影響功能；跑相關測試及 `python3 scripts/check-invariants.py`。`scripts/qa-report.py` 的待驗項不是通過證據。
2. 版面改動按目前 `AGENTS.md` 頂部的 2026-10-29 範圍規則，檢查受影響流程及相關家庭尺寸。只有共用基建或具體跨模組風險才擴大；定期全站回歸另計。所有自動瀏覽器測試靜音。
3. 記錄每項測試的版本、結果和限制。缺依賴、跳過、未觀察到實際結果或證據屬另一版本都不是通過。模擬裝置、真機、機器播音及人耳聽審分開報告。
4. 按授權與專案發布規則檢查 staged diff、CI、merge、Pages 和公開版本，各自核實；任何權限或審批拒絕不可繞過。完成後更新交接，向 Keith 交可撳網址；未發布則明確交代。

## 不要猜

- 遇到複雜架構、部署或資料遷移決策、低信心、測試異常或需求衝突，先保留證據並交 Chief 協調，按需要升級處理。不要因節省成本而跳過必要驗證。
- `docs/handover.md` 內的舊認領和待辦需要對照當前分支、PR、實際檔案及未提交工作，不可按日期直接刪除。
- Supabase 跨裝置同步是暫緩支線；未獲新指示不啟動 migration 或修改登入設定。
- 修改或審查成果時，只取需要的檔案與輸出。遇上未知規則、衝突或驗證無法進行，記下具體證據與限制，向 Chief 回報。
